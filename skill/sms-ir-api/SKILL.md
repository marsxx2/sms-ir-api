# sms.ir API Helper

راهنمای غیررسمی و مستقل برای کار با وب‌سرویس REST سایت [sms.ir](https://sms.ir) — یک سرویس ارسال پیامک ایرانی که برای ارسال OTP، پیامک تبلیغاتی و پیامک گروهی استفاده می‌شود. این skill برای کمک به نوشتن کد صحیح و اجتناب از اشتباهات رایج طراحی شده؛ **وابسته به sms.ir نیست.**

## قبل از هر چیز: خواندن مرجع کامل

جزئیات کامل (پارامترها، مدل پاسخ، نمونه‌کد به ۸ زبان/ابزار، جدول کامل کدهای وضعیت) در فایل `references/api-reference.md` است. برای هر کار واقعی (نوشتن یا بررسی کد ارسال/گزارش‌گیری، رفع خطا بر اساس کد وضعیت، یا فراخوانی هر متد)، **قبل از نوشتن کد این فایل را باز و بخش مربوطه را بخوان** — پارامترهای دقیق، فرمت درخواست/پاسخ و نمونه‌کد آنجاست، نه در این فایل. برای کار با یکی از پنج SDK رسمی، `references/sdks.md` را بخوان.

اگر این skill داخل مخزن اصلی (که شامل پوشه‌ی `docs/` هم هست) در حال استفاده است، `docs/` نسخه‌ی مرجع و انسانی‌خوان همین محتواست؛ محتوای `references/` در این پوشه کپی خودکفا (self-contained) همان مطالب است تا این skill مستقل از مخزن هم قابل استفاده باشد.

## شروع سریع

- **آدرس پایه:** `https://api.sms.ir/v1`
- **احراز هویت:** هدر `X-API-KEY` با کلید خصوصی از پنل «برنامه‌نویسان» — کلید در URL یا Body نمی‌رود.
- **پاسخ همه‌ی متدها:** پوشش یکسان `{ "status": int, "message": string, "data": ... }`. `status: 1` یعنی موفق.
- **واحد زمان:** Unix Time بر حسب UTC.
- **محیط تست:** Sandbox برای تست بدون ارسال واقعی و بدون کسر اعتبار — جزئیات در بخش ۲ مرجع (`references/api-reference.md`).

## کدام متد را استفاده کنم؟

قبل از نوشتن کد، بر اساس نیاز کاربر تصمیم بگیر — انتخاب متد اشتباه باعث رفتار غیرمنتظره می‌شود:

| اگر کاربر می‌خواهد...                                              | از این متد استفاده کن         |
| ---------------------------------------------------------------------| -------------------------------- |
| یک متن ثابت را به یک یا چند شماره بفرستد (از خط اختصاصی خودش)        | **Bulk** (`/send/bulk`)          |
| به هر شماره متن *متفاوتی* بفرستد (نظیر به نظیر)                      | **Like-to-Like** (`/send/likeToLike`) |
| کد تایید (OTP)، فاکتور، یا پیامک با اولویت بالا و تحویل تضمین‌شده‌تر بفرستد | **Verify** (`/send/verify`) — نیازمند تعریف قالب در پنل |
| از یک سیستم قدیمی/ساده که فقط GET/POST به یک URL می‌زند ارسال کند    | **Send via URL** (`/send`)       |
| ارسال زمان‌بندی‌شده را لغو کند                                       | **Delete Scheduled** (`/send/scheduled`) |
| وضعیت تحویل یک یا چند پیامک را پیگیری کند                            | متدهای گزارش (بخش ۴ مرجع)        |

## نکات مهمی که در مستندات رسمی sms.ir نیست

این‌ها یافته‌های عملی هستند که رعایت‌نکردن‌شان باعث باگ می‌شود:

1. **متد اعتبار (`GET /v1/credit`) تعداد پیامک باقی‌مانده را برمی‌گرداند، نه مبلغ ریالی.** اگر کاربر انتظار مبلغ اعتبار حساب را دارد، این تفاوت را حتماً گوشزد کن.
2. **در پاسخ ارسال گروهی/نظیربه‌نظیر، آرایه‌ی `MessageIds` معنای خاص دارد:** مقدار `0` یعنی آن شماره در لیست سیاه است؛ مقدار `null` یعنی شماره نامعتبر است یا متن برای آن مخاطب بیش‌ازحد بلند بوده. کد را طوری بنویس که این دو حالت را جدا از موفقیت واقعی مدیریت کند.
3. **حداکثر ۱۰۰ گیرنده در هر درخواست ارسال گروهی/نظیربه‌نظیر.** برای بیش از ۱۰۰ شماره، درخواست را دسته‌بندی (batch) کن.
4. **بازه‌ی مجاز ارسال زمان‌بندی‌شده:** از یک ساعت بعد تا حداکثر ۳۶۵ روز بعد؛ زمان گذشته را رد می‌کند.
5. **اگر خط اختصاصی «خدماتی» فعال نباشد**، ارسال با متد Bulk ممکن است برای مخاطبانی که پیامک تبلیغاتی را مسدود کرده‌اند نرسد؛ متد Verify از خطوط خدماتی استفاده می‌کند و این مشکل را ندارد.
6. **کد وضعیت HTTP همیشه در بدنه‌ی پاسخ JSON است، نه فقط در HTTP status.** به فیلد `status` در پاسخ نگاه کن، نه فقط کد HTTP.

## SDKهای رسمی

قبل از نوشتن کد خام HTTP، بررسی کن که آیا SDK رسمی برای زبان مورد نظر کاربر وجود دارد — معمولاً ساده‌تر و کم‌خطاتر است. جزئیات کامل هر پکیج (نصب، مرجع متدها، نمونه‌کد) در `references/sdks.md`.

| زبان / فریم‌ورک | نصب                              |
| ----------------- | ----------------------------------- |
| Node.js            | `npm install smsir-js`              |
| PHP / Laravel      | `composer require ipe/smsir-php`    |
| TypeScript         | `npm install sms-typescript`        |
| .NET               | `dotnet add package IPE.SmsIR`      |
| Python             | `pip install smsir-python`          |

اگر هیچ‌کدام مناسب نبود (مثلاً زبان دیگری مثل Go یا Java)، از فراخوانی مستقیم REST با نمونه‌کدهای `references/api-reference.md` استفاده کن.

## نحوه‌ی کار با کاربر

- اگر کاربر می‌گوید «چطور با sms.ir پیامک بفرستم؟» یا مشابه آن بدون جزئیات بیشتر، بر اساس جدول «کدام متد را استفاده کنم؟» بپرس هدفش OTP است یا پیامک عادی/گروهی، و زبان برنامه‌نویسی‌اش را بپرس (یا از کد موجود در پروژه تشخیص بده) تا SDK درست را پیشنهاد بدهی.
- همیشه هنگام نوشتن کد ارسال، مدیریت خطا بر اساس `status` پاسخ و بررسی معنای `MessageIds`/`null` را اضافه کن؛ کد بدون مدیریت خطا برای این API ناقص است.
- اگر کاربر از مقدار بازگشتی متد اعتبار برای منطق مالی (مثل قطع سرویس وقتی «اعتبار ریالی» تمام شد) استفاده می‌کند، حتماً نکته‌ی شماره ۱ بالا را گوشزد کن، چون این یک منبع رایج باگ است.
